# Как записывается опыт

Одно правило для всех агентов (Claude Code, Codex, Antigravity, OpenClaw и других). Опыт — это **повторяемое действие без поиска и ошибок**: в прошлый раз искал, пробовал, ошибался — теперь сразу рабочий способ. Не история, не рассуждения, не пересказ разговора.

## Как опыт всплывает

Хук maxagent сам ищет атомы и показывает агенту текст лучшего целиком — в трёх местах:
1. на сообщение хозяина;
2. перед вызовом инструмента (команда, поиск в сети) — по строкам `когда`;
3. после ошибки команды — по её тексту.

Отдельно «загружать в память» ничего не надо: записал атом в файл — со следующего шага его находит любой агент. Указатель пересобирается сам, только для изменённых файлов.

Поиск двойной: по словам (точные имена: ffmpeg, SSH, `grep -P`) и по смыслу — векторы multilingual-e5-small, без интернета, если модель установлена («сервер вообще живой?» находит «Проверить, жив ли сервер»). Перед вызовом инструмента — только по строкам `когда`, чтобы команда не тянула случайное.

## Когда записывать

Записывать, если в этой задаче:
- пришлось искать (сеть, документация, чужой код, перебор команд);
- что-то не сработало и сделал иначе;
- хозяин дал правило или поправку;
- получился способ, который явно повторится.

Обычные шаги по известному пути — не опыт. Есть атом про это — **поправить его**, а не писать второй.

## Куда

`experience/<вид>/<вещь>.md`, имя латиницей. Вид: `platform` (компьютер, ОС, оболочки), `tools` (программы и сервисы), `code` (языки, библиотеки), `agents` (агенты и их хуки), `craft` (ремесло: видео, тексты, дизайн), `owner` (как работает хозяин). Знание только для одного проекта — в `projects/<проект>/`. Одна вещь — один файл: о чём знание (ffmpeg, SSH на сервер), а не где узнал.

Папка `experience/shared/` — общие наборы чужого опыта: их не править. Чужой атом пригодился — `adopt` (см. `agents/shared-experience.md`).

## Файл

```
---
title: Командная строка Windows — PowerShell 5.1, Git Bash
task: Выполнить команду и не ошибиться с синтаксисом, путями и кодировкой
aliases: терминал, shell, PowerShell, bash, cmd, команда
---

### <атом>
...
```

- `title` — вещь одной строкой.
- `task` — какие задачи решает файл, одной строкой: это колонка «Когда читать» в индексе `experience.md`.
- `aliases` — слова, которыми эту вещь будут искать: на вашем языке и по-английски, названия команд.

## Атом

Раздел `###` — одна задача, одна ловушка или одно правило. Целиком не больше **900 знаков**: он показывается агенту целиком.

```
### Связать команды в PowerShell 5.1
- когда: PowerShell && · цепочка команд PowerShell
- когда: The token '&&' is not a valid statement separator
- вещь: Windows · PowerShell 5.1
1. Вместо `A && B` — `A; if ($?) { B }`; без условия — `A; B`.
- проверка: команда отработала без ошибки синтаксиса
- ловушка: не `A && B` в PowerShell 5.1 — ошибка разбора
- источник: свой опыт, 05.11.2026
```

| Строка | Обязательно | Что писать |
|---|---|---|
| `- когда:` | да, можно несколько | триггеры: словами просьбы, намерения агента, имена инструментов и команд, текст ошибки. Части через ` · `; часть срабатывает перед вызовом, если **все** её слова есть в команде |
| `- вещь:` | да | 2–6 предметов через ` · ` |
| шаги | да | что делать: нумерованные шаги, команды в `` ` `` или в блоке кода |
| `- проверка:` | если есть | что должно получиться |
| `- ловушка:` | сколько есть | «не X — потому что Y», одной строкой |
| `- источник:` | да | свой опыт / документация / хозяин + дата |

Порядок строк: `когда` → `вещь` → шаги → `проверка` → `ловушка` → `источник`.

- Триггеры — так, как их скажут: «зайди на сервер», «проверь пользователей» (повелительная форма и неопределённая — разные слова для поиска по словам).
- В триггере команды должно остаться не меньше двух значимых частей: `python <<`, `grep -P`, `git add -A`. Одно слово (`python`, `grep`) сработает на любой вызов. Значимы слова, ключи (`-P`) и `&&`, `||`, `<<`; пути и кавычки не считаются.
- Триггер инструмента — с его именем: `PowerShell &&`, а не `&&` (в Bash `&&` законно, атом сработал бы зря).
- **Нет данных — нет строки.** Никаких заглушек и TODO.
- Пароли, ключи, токены — никогда. Только **где лежат**: «пароль — в менеджере паролей».
- Обычная орфография: пробел между словом и числом, между русским словом и латиницей.
- Строка не длиннее 200 знаков; длинное — шагами.

## Проверка — одна команда для любого агента

```
node ~/.maxagent/tools/experience-engine.js lint experience/<вид>/<вещь>.md
node ~/.maxagent/tools/experience-engine.js find "<слова задачи>"
```

`lint` → «ошибок нет». `find` словами будущей просьбы → новый атом наверху. Хук после записи в `experience/` запускает `lint` сам и показывает ошибки; хук перед коммитом не пропустит файл с ошибками.

Индекс `experience.md` собирается из шапок файлов, руками его не править:

```
node ~/.maxagent/tools/experience-index.js
```

Порог поиска по смыслу (`SIM_GATE` в движке) зависит от размера базы: когда атомов стало намного больше, прогнать нужные просьбы и посторонние фразы (`node ~/.maxagent/tools/experience-engine.js explain "<фраза>"`). Посторонние должны быть ниже порога, нужные — выше.
