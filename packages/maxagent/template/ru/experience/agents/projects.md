### Продолжить работу по проекту: где остановились
- когда: продолжи проект · где мы остановились · задача по проекту · активная задача
- вещь: projects.md · карточка проекта
1. Включён репозиторий — сначала `git pull --rebase`, потом читать.
2. `projects.md` → строка проекта → `projects/<имя>/README.md` → активная задача. С нуля не начинать, если записана точка останова.
- ловушка: прочитал проект без pull — взял устаревшую версию и переспросил то, на что хозяин уже ответил
- источник: опыт maxagent, 2026

### Записать задачу или инцидент проекта
- когда: заведи задачу проекта · запиши инцидент · карточка задачи · пять блоков
- вещь: projects/<имя>/tasks · статусы
1. Файл `projects/<имя>/tasks/<дата>-<название>.md` (инцидент — `projects/<имя>/incidents/…`); заготовка — `projects/_example/tasks/_TEMPLATE.md`.
2. Пять блоков: симптом; диагностика; истинная причина; что сделано; как быстро проверить при повторении (команда и ожидаемый результат).
3. Статусы — у этапов и задач, не у проекта: `[▶]` в процессе, `[⏸]` пауза или блокер, `[✓]` готово, `[ ]` в планах. `README.md` проекта — только карта: цель, дерево этапов, ссылка на активную задачу.
- источник: опыт maxagent, 2026

### Закончить задачу проекта
- когда: задача закончена · зафиксируй · обнови статус проекта · двойная фиксация
- вещь: projects.md · опыт · git
1. Статус этапа или задачи в `projects/<имя>/…`, строка проекта в `projects.md`.
2. Новое знание (выяснял, что-то не сработало, правило хозяина, повторяемый способ) — атомом в `experience/` по `_spec.md`, проверка `lint`.
3. Включён репозиторий — `git add <свои пути>` → commit → `git pull --rebase` → push; не вышло — строка в `sync.md`.
